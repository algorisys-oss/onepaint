# Deliberate divergences from happypaint

Each entry says what differs, why, and when it goes away. Keep this list
short by fixing entries, not by growing it.

| # | Area | onepaint | happypaint | Why / when it goes away |
|---|---|---|---|---|
| 2 | Document depth | 8-bit documents match happypaint (specs 49, 50): premultiplied sRGB bytes, gamma-space blending with its fixed-function multiply, screen and add. 32F documents work in RGBA16F; their `depth` is kept on save. | 32F | 32F storage later. |
| 4 | Tile dedup key | PNG bytes | Hash of the GPU readback, shared between layer and mask tiles | Avoids a latent cross-namespace collision (see spec 05). Readers are unaffected. |
| 5 | Thumbnail | JPEG composited over white | JPEG from a canvas `toBlob` | It is cosmetic only. |
| 6 | Pen pressure off Wayland | Velocity-synthesised pressure on X11 and macOS (winit exposes no tablet pressure there); Wayland reads the pen through tablet-v2 | Pointer Events pressure and tilt | XInput2 and native macOS backends are planned. |
| 8 | Merge down | Like happypaint, draws the upper layer onto the lower layer's raw pixels with its own opacity and blend mode (advanced modes included), in the document's space; the lower layer keeps its opacity, mode and mask. onepaint also applies the upper layer's mask. | `drawTextureOnto` draws the upper layer's raw texture, so pixels its mask hid show again after the merge (`paint-engine.ts:7665`) | Applying the mask keeps what you see. Switch to happypaint's behaviour if parity is wanted here. |
| 10 | Adjustment maths precision | f32 CPU reference (spec 10) | GPU with 16F storage and an 8-bit LUT texture | Within 16F rounding; the LUT lookup replicates the texel-centre bilinear sampling. |
| 11 | Text rendering | cosmic-text/swash with system fonts; the outline is a dilated glyph mask. Balloons fill and stroke the union of body, lobes and tail (spec 28) | Canvas2D `fillText`/`strokeText`. The balloon path is filled nonzero, so the tail (wound the other way) cuts a transparent wedge from the centre to the wall, and `stroke()` also draws the tail base and the cloud's inner lobe arcs and ellipse | Metrics differ slightly by font engine. The balloon difference fixes a visible happypaint bug that contradicts its own comment and manga-spec P3 ("no seam", "outlines the union"); revert to nonzero if exact parity is wanted. |
| 12 | PSD text layers | Exported as raster layers (their rendering); no `TySh` editable text | Editable text through ag-psd | Port the `TySh` engine data writer. |
| 13 | Filter handles | Centres, ends and blur pins are panel sliders | On-canvas handles (`filter-handles.ts`) | Port the handle geometry with the canvas overlay work. |
| 14 | Lightning raster | The bolt path is identical (mulberry32, checked against a golden). Strokes are antialiased round-capped polylines with a Gaussian shadow of σ = `shadowBlur`/2 | Canvas2D `stroke` with `shadowBlur` | No Canvas2D in Rust. The glow profile differs slightly. |
| 15 | Pattern fill | Built-in and imported `patternImage` patterns, sampled bilinearly with repeat, on the CPU and the GPU alike | Mipmapped sampling on the GPU | Mips in `gpu`. Only zoomed-out minification differs. |
| 16 | Screentone | `fwidth` is estimated from neighbouring doc pixels; never flattened for preview | GPU `fwidth`; preview flattens unresolvable dots to grey | The flattening is preview-only and needs the view scale, so it comes with the GPU canvas. Export output already matches. |
| 17 | `sin` hashes (glitch, wind, tone sand, Dissolve) | CPU f32 `sin`; Dissolve uses a PCG integer hash of the doc pixel, the same on CPU and GPU | GPU `sin` | Large arguments differ between GPUs too. The CPU stays the oracle for the wgpu port. Dissolve's dither pattern differs from happypaint's; its density matches. |
| 19 | Rulers on a rotated canvas | Hidden while the canvas is rotated (pinned rulers only) | A document-attached tick band that turns with the artwork | Draw the doc-edge band when `rulers_pinned` is false. |
| 20 | Video export | MP4 (H.264 via OpenH264) for animations and timelapses; no WebM; the timelapse draws no pointer cursor | Also WebM via MediaRecorder, the fallback where WebCodecs H.264 is missing; the timelapse overlays the recorded pointer | OpenH264 is always present here, so MP4 plays everywhere. VP8/VP9 would need libvpx. onepaint recordings log engine events, not pointer positions. |
| 21 | Exposure-sheet grid | Retiming and every grid edit are undoable, one step each (a drag is one) | `setNodeAnimMeta` has no undo; add-track and add-sheet are several steps | Undo should cover what the user did. The batch timing ops are one step each too, and on sheets with explicit starts they push later sheets right instead of overlapping them. |
| 22 | Recordings | `.onepaint-rec` (start document, lossless tiles, session state, serde command log); timelapse as GIF | `.happypaint-rec` logs PaintEngine calls; MP4 timelapse | The engines differ, so logs are not interchangeable. |
| 23 | Brush import resampling | Tip and grain bitmaps are resized with a triangle filter; the ABR tip angle and roundness are baked with bilinear sampling | Canvas2D `drawImage` with high-quality smoothing | No Canvas2D in Rust. Edges differ by a few levels; shapes, sizes and placement match. |
| 24 | Imported brush ids | Content hashes (`imported-…`, `custom:…`, `customgrain:…`); importing the same file again replaces the brushes | Random ids; a second import adds duplicates | Stable ids make the saved library and `.happybrush` round trips exact. Kept unless duplicates are wanted. |
| 25 | Brush studio editing model | The engine's current preset is the edited brush (`SetBrushPreset`); Reset re-selects the stored preset. Custom brushes can be renamed and saved over; new ids are `b_<n>`. The studio opens from the brush popover; there is no compact all-settings panel. | Flat override fields folded by `effectiveBrush()`; "Save current" only, no rename or overwrite; ids `b_<time36>_<rand36>`; the panel maximizes into the studio | One source of truth, and domain crates may not read the clock. Rename and save-over are additions. |
| 26 | Brush studio controls | No hue-shift source control (as in happypaint, it comes from the preset); size scaling and force pressure are in Settings (spec 34) | All present | The stroke engine does not implement these yet; each control lands with its engine feature. Preset values are kept untouched. |
| 27 | Brush preview and try-it pad | CPU `StrokeEngine` raster; the preview S-curve runs top-down (y down) | WebGL `BrushEngine`; the curve is drawn y-up, so it is mirrored | Mirror only; same path, pressure and tilt. |
| 28 | Panel borders | There is always one "Panel borders" layer, rebuilt by every panel operation, including a new layout. It holds one path object per distinct border width and colour. | `createPanelGrid` adds a new border layer each time, and a rebuild strokes the whole page at one width (the last panel's) | onepaint lets the gutter and border be set per page and per panel, so the borders have to follow. Kept. |
| 29 | Panel active layer | After a layout or a new frame, the panel's "Art" layer is active | The panel group is active | You can paint straight away. Kept. |
| 30 | Panel reshape and move | Applied once the drag passes 4 doc px; live edits coalesce until release | Applied from the first pixel; `setPanelOutline`, then `commitPanelOutline` | A tap pushes no undo step either way. Kept. |
| 31 | Open-tab cap | Opening past the cap closes the least recently active tab that has no unsaved changes; if every tab is unsaved, none closes | Closes the oldest tab, saved or not | Never drop unsaved work silently. Kept. |
| 32 | Impasto relief and undo | Paint relief is recorded in the stroke's undo step, together with the paint | Brush relief is not in history; the alpha gate hides leftovers, so undoing a thick stroke and repainting thinly brings old ridges back | happypaint's own header lists this as a slice simplification. COW tiles make recording it cheap. |
| 33 | Bevel sliders | Bevel and Soften re-derive the relief when the slider is released (one undo step) | Re-derived on every input event | The CPU distance transform is full-canvas; per-event derivation would also flood history. |
| 34 | Relief under transforms | Free transform, liquify, flip and filters leave the height field in place | The field moves with the pixels (`beginFieldTransform`) | Port with the GPU transform path; the alpha gate hides relief left outside the paint. |
| 35 | Live wet simulation | wgpu compute (or CPU with rayon when no GPU), f32 state, activity blocks; one readback per tick | GPU fragment passes, RGBA16F state | Results match the CPU oracle within 5e-4 per batch; `sin` hashes as divergence 17. The canvas composite is CPU, hence the readback. |
| 36 | Wet session and other strokes | A dry-brush, smudge, liquify or gradient stroke dries the wet session first (two undo steps) | The sim pauses during the stroke and the session's single entry later includes the dry stroke | Keeps every stroke individually undoable. |
| 37 | Paper in recordings | The recording's start document carries the paper, so replays start on it | The recorder header has no paper; only mid-recording `setPaper` calls replay | A replay should match what was painted. |
| 38 | Blender toggle off | Turning Blender off stops the levelling and restores the preset's tip and mix | A preset born a blender (`oil-blender`) keeps levelling relief while its toggle reads Off (`blend` falls back to the preset's) | The toggle should mean what it says. |
| 39 | Shortcut rebinding | Reserved keys are refused at capture. "Reset all" clears everything. `+` combos display correctly. The Documents actions are listed. Modifiers match exactly. Stored overrides are validated. | Reserved keys bind but never fire. "Reset all" merges `{}` and clears nothing. `formatCombo` mangles `+`. Documents actions aren't listed. | happypaint bugs, not features. |
| 40 | Display-P3 export | The composite is converted to P3 values and tagged with the P3 profile | Tags the export P3; the export canvas draws the sRGB composite | Tagged and encoded values have to agree, or colours shift in managed viewers. |
| 41 | Tool bar default | Retired (spec 65): the tool bar docks as a left rail by default, as happypaint | — | — |
| 42 | Layers home | Retired (spec 65): Layers docks right and is open by default, Properties under it | — | — |
| 43 | Extra dockable panels | Guides and Tool options (the current tool's settings) dock and float too; the palette moves out of the Colour panel while the Palettes panel is open | Only the eight panels in `DOCK_PANEL_IDS` | Every tool's controls can be docked. |
| 44 | Status bar footer | Version only | Version, a What's-new dot and the © line | onepaint has no release notes dialog, and its licence notice lives in the About text. |
| 45 | Docked panel width | Bodies fill the dock's width | Fixed-width bodies | egui lays out to the host; nothing is cut off at the 190 px minimum. |
| 46 | Undo with the Move tool's box open | An untouched box steps aside and the undo runs | Same (the transform is only pending once it changes) | Was a onepaint bug: Undo after Apply cancelled the empty box instead. Listed so the parity check covers it. |
| 47 | Vector mask edges | Each path is flattened (0.05 px) and filled with 16 sub-scanlines a pixel and exact horizontal coverage, per tile | Canvas2D `fill`, whatever anti-aliasing the browser does | No Canvas2D in Rust. Interiors and the ops' maths match; edge pixels differ by a few levels. happypaint's quirks are kept: open paths fill as closed, and Pen subpaths convert as closed paths. |
| 48 | Feathered masks | The blurred mask is stored as an f16 tile | The blur output texture | Masks are f16 tiles everywhere in onepaint; the difference is below 1e-3. |
| 49 | Side sliders | Size, opacity, undo and redo; placement from View ▸ Workspace, Settings, or by pulling the grip off an edge | Also an eyedropper square (one pick, then back to the tool) | The eyedropper is a tool on the rail and Alt-click. |
| 51 | Layer style distance field | Exact Euclidean distance (Felzenszwalb's transform) per tile, over the tile ± twice the effects' reach | Jump flooding (JFA+1) over the whole canvas | Exact is cheaper per tile and is the oracle the GPU pass will match; JFA's rare misses move a wide effect's edge by under a pixel. The gradient overlay samples onepaint's 1024-entry ramp (happypaint's style LUT is smaller): a sub-level difference. |
| 50 | PSD after a canvas resize | A resized document is written as a new 8-bit RGB file | The source's shell (mode, depth, resources) is kept and the layers re-encoded | onepaint's PSD source only applies at the size it was read at; same-size saves keep the mode, depth and version (spec 64). |
| 52 | Procedural paper sampling | The paper tile is sampled bilinearly at every zoom and DPI | The physical papers' textures have trilinear mipmaps | The 0.18 mm texel is magnified at 150 dpi and above; only low-DPI documents minify it, where onepaint's tooth aliases slightly. |
| 53 | 1-bit PSD rows | Each row starts on a byte, as Photoshop stores them | `sampleAt` indexes bits without the row padding | happypaint's bitmaps shear when the width isn't a multiple of 8. |
| 54 | Mixer patch load | Each of the 64² texels averages 4 × 4 bilinear taps of its footprint | Two bilinear blits: the brush square into 256², then into 64² | Fewer aliasing artefacts from large brushes; the colours agree otherwise (spec 63). |
| 55 | View menu sections | Guides, Panels, Capture and Workspace open as submenus of View | One long list with section captions | Inline, the View menu is taller than a laptop window (spec 65). |
| 56 | Command palette entries | Every enabled menu row plus the rebindable actions, with a short synonym table; disabled rows are left out | A hand-written dictionary of ~250 commands (`command-items.ts`) | The menus are the registry, so new commands appear in the palette without a second list to keep in step. |
| 57 | Live taper tail cadence | Redrawn once per frame, when the canvas takes its dirty tiles | Redrawn on every pointer move | The tail is display-only; a 240 Hz pen sends ~4 moves a frame, and onepaint's dabs are on the CPU. |
| 58 | Partly unreadable file | Opens with the broken tiles blank and a notice; the tab is not bound to the file, so Save asks for a new name | Copies the stored drawing to the gallery as "<name> (original)" before the next save | A desktop file stays on disk until the user overwrites it, and autosave writes elsewhere; asking for a new name protects it without a second copy. |
| 59 | Auto-save | A recovery copy in the app data folder, on the chosen schedule; Save writes the file and drops the copy | The browser copy is the drawing itself: Ctrl+S, leaving the editor and hiding the tab all write it | On the desktop the file is the drawing; the copy only exists for a crash. |
| 60 | Memory estimate | Half the system RAM; a layer costs its painted tiles (a full one 4 or 8 B/px); Document Properties shows the memory held now | Half of `navigator.deviceMemory`; every layer is a canvas-sized texture | onepaint layers are sparse CPU tiles, so the held memory is known exactly; the browser hides graphics memory. |
| 61 | Transform aspect link | The chain button in the Transform & Align panel; the Move tool's handles keep the ratio with Shift | The same switch as the Move tool's Uniform toggle | onepaint's Move tool has no Uniform toggle (Shift already constrains a drag), so the link is the panel's own. |
