# Deliberate divergences from happypaint

Each entry says what differs, why, and when it goes away. Keep this list
short by fixing entries, not by growing it.

| # | Area | onepaint | happypaint | Why / when it goes away |
|---|---|---|---|---|
| 1 | Blend mode `pigment` | Composites as `normal` | Kubelka–Munk glaze (`engine/color/pigment.ts`) | The KM port is planned for slice 2+. |
| 2 | Document depth | Every document works internally in RGBA16F linear. 8-bit and 32F files open as 16F; their `depth` is kept on save. | Per-document 8-bit (gamma-space compositing, fixed multiply quirk) or 32F | 8-bit and 32F modes come in a later slice. |
| 3 | Off-canvas pixels | Dropped on save. Existing `overflow` chunks are passed through unchanged. | Saved as an `overflow` PNG | Planned with the move/transform tool. |
| 4 | Tile dedup key | PNG bytes | Hash of the GPU readback, shared between layer and mask tiles | Avoids a latent cross-namespace collision (see spec 05). Readers are unaffected. |
| 5 | Thumbnail | JPEG composited over white | JPEG from a canvas `toBlob` | It is cosmetic only. |
| 6 | Pen pressure on Linux | Velocity-synthesised pressure (winit exposes no tablet pressure on X11/Wayland) | Pointer Events pressure and tilt | A tablet backend (Wayland tablet-v2, XInput2, Windows Ink, macOS) is planned. |
| 8 | Merge down | Bakes the upper layer into the lower one and keeps the lower layer's opacity and blend mode | (to verify) | Check against happypaint's `mergeDown` behaviour. |
| 10 | Adjustment maths precision | f32 CPU reference (spec 10) | GPU with 16F storage and an 8-bit LUT texture | Within 16F rounding; the LUT lookup replicates the texel-centre bilinear sampling. |
| 11 | Text rendering | cosmic-text/swash with system fonts; the outline is a dilated glyph mask. Balloons fill and stroke the union of body, lobes and tail (spec 28) | Canvas2D `fillText`/`strokeText`. The balloon path is filled nonzero, so the tail (wound the other way) cuts a transparent wedge from the centre to the wall, and `stroke()` also draws the tail base and the cloud's inner lobe arcs and ellipse | Metrics differ slightly by font engine. The balloon difference fixes a visible happypaint bug that contradicts its own comment and manga-spec P3 ("no seam", "outlines the union"); revert to nonzero if exact parity is wanted. |
| 12 | PSD text layers | Exported as raster layers (their rendering); no `TySh` editable text | Editable text through ag-psd | Port the `TySh` engine data writer. |
| 13 | Filter handles | Centres, ends and blur pins are panel sliders | On-canvas handles (`filter-handles.ts`) | Port the handle geometry with the canvas overlay work. |
| 14 | Lightning raster | The bolt path is identical (mulberry32, checked against a golden). Strokes are antialiased round-capped polylines with a Gaussian shadow of σ = `shadowBlur`/2 | Canvas2D `stroke` with `shadowBlur` | No Canvas2D in Rust. The glow profile differs slightly. |
| 15 | Pattern fill | Built-in patterns only, sampled bilinearly with repeat | Also imported `patternImage` PNGs; mipmapped sampling | The image needs a decoder in `formats` and mips in `gpu`. Until then an imported pattern falls back to the built-in. |
| 16 | Screentone | `fwidth` is estimated from neighbouring doc pixels; never flattened for preview | GPU `fwidth`; preview flattens unresolvable dots to grey | The flattening is preview-only and needs the view scale, so it comes with the GPU canvas. Export output already matches. |
| 17 | `sin` hashes (glitch, wind, tone sand) | CPU f32 `sin` | GPU `sin` | Large arguments differ between GPUs too. The CPU stays the oracle for the wgpu port. |
| 19 | Rulers on a rotated canvas | Hidden while the canvas is rotated (pinned rulers only) | A document-attached tick band that turns with the artwork | Draw the doc-edge band when `rulers_pinned` is false. |
| 20 | Animation video export | GIF and PNG-sequence zip only | Also MP4/WebM via WebCodecs | Needs a native encoder (openh264 or ffmpeg); a dependency decision for the owner. |
| 21 | Exposure-sheet editing | Tracks render, play and onion correctly, but the timeline shows the active track as a strip | A row-per-track grid with drag retiming, markers and out-of-pegs | UI work only; the model is complete. |
| 22 | Recordings | `.onepaint-rec` (start document, lossless tiles, session state, serde command log); timelapse as GIF | `.happypaint-rec` logs PaintEngine calls; MP4 timelapse | The engines differ, so logs are not interchangeable. |
| 23 | Brush import resampling | Tip and grain bitmaps are resized with a triangle filter; the ABR tip angle and roundness are baked with bilinear sampling | Canvas2D `drawImage` with high-quality smoothing | No Canvas2D in Rust. Edges differ by a few levels; shapes, sizes and placement match. |
| 24 | Imported brush ids | Content hashes (`imported-…`, `custom:…`, `customgrain:…`); importing the same file again replaces the brushes | Random ids; a second import adds duplicates | Stable ids make the saved library and `.happybrush` round trips exact. Kept unless duplicates are wanted. |
| 25 | Brush studio editing model | The engine's current preset is the edited brush (`SetBrushPreset`); Reset re-selects the stored preset. Custom brushes can be renamed and saved over; new ids are `b_<n>`. The studio opens from the brush popover; there is no compact all-settings panel. | Flat override fields folded by `effectiveBrush()`; "Save current" only, no rename or overwrite; ids `b_<time36>_<rand36>`; the panel maximizes into the studio | One source of truth, and domain crates may not read the clock. Rename and save-over are additions. |
| 26 | Brush studio controls | No hue-shift source control (as in happypaint, it comes from the preset); size scaling and force pressure are in Settings (spec 34) | All present | The stroke engine does not implement these yet; each control lands with its engine feature. Preset values are kept untouched. |
| 27 | Brush preview and try-it pad | CPU `StrokeEngine` raster; the preview S-curve runs top-down (y down) | WebGL `BrushEngine`; the curve is drawn y-up, so it is mirrored | Mirror only; same path, pressure and tilt. |
| 28 | Panel borders | There is always one "Panel borders" layer, rebuilt by every panel operation, including a new layout. It holds one path object per distinct border width and colour. | `createPanelGrid` adds a new border layer each time, and a rebuild strokes the whole page at one width (the last panel's) | onepaint lets the gutter and border be set per page and per panel, so the borders have to follow. Kept. |
| 29 | Panel active layer | After a layout or a new frame, the panel's "Art" layer is active | The panel group is active | You can paint straight away. Kept. |
| 30 | Panel reshape and move | Applied once the drag passes 4 doc px; live edits coalesce until release | Applied from the first pixel; `setPanelOutline`, then `commitPanelOutline` | A tap pushes no undo step either way. Kept. |
| 31 | Open-tab cap | Opening past the cap closes the least recently active tab that has no unsaved changes; if every tab is unsaved, none closes | Closes the oldest tab, saved or not | Never drop unsaved work silently. Kept. |
| 32 | Impasto relief and undo | Paint relief is recorded in the stroke's undo step, together with the paint | Brush relief is not in history; the alpha gate hides leftovers, so undoing a thick stroke and repainting thinly brings old ridges back | happypaint's own header lists this as a slice simplification. COW tiles make recording it cheap. |
| 33 | Bevel sliders | Bevel and Soften re-derive the relief when the slider is released (one undo step) | Re-derived on every input event | The CPU distance transform is full-canvas; per-event derivation would also flood history. |
| 34 | Relief under transforms | Free transform, liquify, flip and filters leave the height field in place | The field moves with the pixels (`beginFieldTransform`) | Port with the GPU transform path; the alpha gate hides relief left outside the paint. |
| 35 | Live wet simulation | CPU (rayon), f32 state, activity blocks; ~8 ms per step for a 600 px wash | GPU fragment passes, RGBA16F state | GPU compute is the follow-up for large washes. Results match within f16 rounding; `sin` hashes as divergence 17. |
| 36 | Wet session and other strokes | A dry-brush, smudge, liquify or gradient stroke dries the wet session first (two undo steps) | The sim pauses during the stroke and the session's single entry later includes the dry stroke | Keeps every stroke individually undoable. |
| 37 | Paper in recordings | The recording's start document carries the paper, so replays start on it | The recorder header has no paper; only mid-recording `setPaper` calls replay | A replay should match what was painted. |
| 38 | Blender toggle off | Turning Blender off stops the levelling and restores the preset's tip and mix | A preset born a blender (`oil-blender`) keeps levelling relief while its toggle reads Off (`blend` falls back to the preset's) | The toggle should mean what it says. |
